## Performance Test: Latency (RTT - PingPong)

This test takes into account the latency introduced by the serialization of a CARLA data frame, the network transmission and the deserialization of the data structures generated by Fast DDS (with XCDR standard).

### Test Architecture
The benchmark employs a synchronous *ping-pong* architecture to measure the **RTT (Round-Trip Time)** with nanosecond precision:

1. **Publisher (Ping):** Is the active node. It sends a message (ping) and blocks its execution thread, waiting for the reply. Upon receiving the echo, it calculates the elapsed time, divides it by two (One-Way latency) and sends the next message.
2. **Subscriber (Pong):** Is the passive node. It listens on the network and, when a valid structure is recived, it is injected back into the network (pong) without performing any processing.

### Execution Phases
1. **Discovery:** Both nodes locate each other on the local network (Fast DDS multicast).
2. **Warm-up:**: The publisher sends 100 samples (defined on data_typesPublisherApp) to stabilize CPU cache and other OS or network resources, preventing cold start anomalies.
3. **Main test:** 10000 data samples (defined on data_typesPublisherApp) are sent sequentially, measuring their taken times (`std::chrono::high_resolution_clock`).
4. **Results:**: The application calculates and outputs the latency metrics, in the same way as eProsima Latency Test (v3.6.1).

### Usage
```bash
# Terminal 1 (Ponger)
./Latency_Test subscriber

# Terminal 2 (Pinger)
./Latency_Test publisher

```
*Verification tests executed under Kernel: Linux 6.12.90+deb13.1-amd64*
